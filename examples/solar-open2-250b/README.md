# Case study: Solar-Open2-250B — the slice-blind gate autopsy, and what it cost a 4.5 bpw MoE

*(Interim — campaign in flight as of 2026-07-24. Numbers below are verified measurements, each reproduced
in ≥2 independent runs unless noted; pending items are marked.)*

The model: **Solar-Open2-250B** (Upstage) — 250B MoE, 48 hybrid layers (12 full-GQA @ 0,4,…,44 + 36 KDA
linear-attention), 320 routed + 1 shared expert, top-8, hidden 4096, vocab 196608 (untied head,
Korean-heavy tokenizer). Ported to MLX via an mlx-lm fork (`solar_open2` arch; stock mlx-lm rejects the
model type). Korean-centric target distribution ⇒ calibration/eval trio = EN/code/**KO**
(`ALIS_DWQ_LANG_SLICE=KO:…`).

## Builds

| build | role | actual bpw (name drift!) | size | recipe |
|---|---|---|---|---|
| T-q8 | teacher / disclosed reference | 8.5 | 266 GB | flat 8b/g64 |
| Q | quality tier | **5.0** ("Q-4.5bpw") | 146 GB | flat 4b/g32, router 8b |
| M | main driver | **4.5** ("M-3.5bpw") | 131 GB | flat 4b/g64, router 8b |
| F | floor | 2.25 | 66 GB | flat 2b/g128, router 8b → clip-search |
| M-dwq / Q-dwq / F-dwq | DWQ'd tiers | same | +adapters/scales | K=8, lr 1e-6, seed 7, 180/20 samples |

The predicate that produced all four was effectively **two rules** — router `mlp.gate` → 8b/g64, everything
else → the CLI global. That detail comes back below.

## The EN regression autopsy (why this case study exists)

M-DWQ shipped a real improvement **and** a real regression in the same run:

| vs T-q8 ref | overall | EN | code | KO | EN loop (256-tok greedy) |
|---|---|---|---|---|---|
| M-base | 0.08018 | 0.05482 | 0.05207 | 0.13365 | **LOOPED cycle=len17** (distinct4 0.206) |
| M-dwq | 0.07627 (−4.9%) | **0.05723 (+4.4%)** | 0.04268 (−18.0%) | 0.12889 (−3.6%) | **clean** (0.375; teacher 0.411) |

And the quality tier: **Q has the best KLD of any candidate (0.06112) yet LOOPS on EN greedy
(cycle=len23)** — KLD alone cannot see the failure the loop probe was built for, and the loop probe
alone cannot see EN's KL tax. Report both.

Mechanism, established by code audit + adversarial review (codex) + independent re-measurement:

1. **The keep-best gate is one token-weighted scalar** over 20 valid rows (`layerwise.py`). KO per-token
   KL was ~2.4× EN's, so KO carried ~4× the loss-mass — a round could (and did) shave KO/code while
   taxing EN, and the scalar improved. **All shipped effects — loop fix AND EN regression — came from the
   single accepted round 1 (deepest layers L40-47 + extras); rounds 2-6 all reverted.**
2. **It is not valid-set underrepresentation.** Reconstructed slice labels: EN 9 / KO 8 / code 3 of 20
   (45% EN) — EN regressed anyway. Mix-quantity fixes target the wrong variable.
3. **Slice labels are seed-origin, not loss-token language.** ~86% of each calibration row is the
   generator's continuation; KO-seeded rows carry heavy English thinking. A per-slice gate must hash and
   label actual token spans, not trust corpus tags.
4. **Surrogate ≠ final metric.** Training/validation run top-1024-teacher-column KL at T=2.0; the ship
   metric is full-vocab KL at T=1. A round can improve the first and regress the second.
5. **Off-policy calibration data carries the defect.** The calibration text was self-generated by the
   quantized student — its EN loops are baked into the inputs; teacher-logit swaps don't fix input
   distribution.
6. **Weak-teacher slices drag the student.** M's teacher was Q — itself EN-damaged (EN KL 0.048, EN
   looping). Capacity-mismatch literature (undistillable slices; BitDistiller's 7B>13B anomaly) predicts
   exactly this drag. **Distill from the strongest reference you can load** — for this campaign the 8-bit
   build; mlx-lm's own docs: an 8-bit DWQ teacher is "usually as good as 16-bit".

Reference integrity note: T-q8 self-KLD = 0.00000 (bit-exact reproduction of the dumped reference) —
the pipeline is deterministic; two independent eval runs of every number above matched exactly. The
`±0.00344` printed by `eval_kld` is the standard error of the 3072-position mean, **not** a
reproducibility σ.

## The fix: per-slice acceptance gate (new, opt-in)

`ALIS_DWQ_VALID_SLICE_MANIFEST=<json>` + `ALIS_DWQ_EN_GATE_EPS=<0..0.25>` (must be set together):
`validate()` verifies per-ordinal input/target sha256 against a manifest (fail-closed), returns
per-slice token-weighted losses, and a round is kept only if **overall improves strictly** (tie now
reverts) **and** EN ≤ init×(1+ε). Off = byte-identical legacy behavior. Synthetic tests cover
accept/reject/tie/NaN/hash-tamper. Gate-noise math for small valid sets: at an assumed relative σ≈4.5%
and ~1/6 accept rate, ε=1% passes a neutral round 59% of the time but still passes a true +4.4%
regression 23% of the time — **small-sample ε cannot replace a better gate metric**. The designed
upgrade is a T=1 full-vocab **EN sentinel** (own reference dump, ~192 MiB/512-token panel): train on
top-1024/T=2 as before, but accept on the same quantity you ship. Qualification before any real run:
the new gate must demonstrably reject the known-bad M-dwq round — if it can't, the design is wrong, not
the build.

## The predicate audit (F's structural weakness)

Motivated by the sister campaign's handoff (Motif-3-Beta): router + expert-bias fp, latent chokepoint
8-bit, embed/head 6-bit. Our audit of what the 2-rule predicate actually produced:

| tensor group | Motif bar | T-q8 | Q | M | F |
|---|---|---|---|---|---|
| KDA state projections (`f_a/f_b/b_proj`, the `wkv_a` analog) + output gate (`g_a/g_b`) ×36 | high bits | 8b | 4b | 4b | **2b/g128** |
| embed + lm_head (untied, KO tokenizer) | 6b | 8b | 4b | 4b | **2b/g128** |
| attention + shared expert | above floor | 8b | 4b | 4b | **2b/g128** |
| router / expert bias | fp / fp | 8b / **f32** | 8b / f32 | 8b / f32 | 8b / f32 |

F landed at 66 GB against a 72–79 GB budget — **6–13 GB of unspent budget while its recurrent-state
projections sat at 2-bit**. Clip-search re-rounds codes but cannot add codebook capacity, and DWQ trains
scales/biases on top of the same codebooks — **neither pass can repair a 2-bit chokepoint; only
requantization with a per-tensor recipe can.** Promotion economics (vs on-disk bytes): F chokepoint+gate
→ 8b is **+96 MB**; embed/head → 6b is +856 MB; the full Motif-bar set is ≈ +2.9 GB → ~69 GB, in budget.
Corroboration from our own telemetry: F's worst-utilization tensors (L0 `g_a_proj` ~65%, L0 `g_proj`
62.8%, L0 shared `gate_proj` 47.5%) are exactly the chokepoint/gate/shared groups.

Runbook lesson: the F recipe *intended* "experts 2-bit, attention/shared higher" — a comment the 2-rule
predicate could not express. **Recipe intent must live in the predicate, not the docs.**

## Landmines found (patched or documented)

- `mx.split` on >2³¹-element tensors silently corrupts ([mlx#3836](https://github.com/ml-explore/mlx/issues/3836)).
  Solar's fused `experts.gate_up_proj` would be 1.56×2³¹ — the shipped builds never took that code path
  (per-expert checkpoint layout), but any HF-layout re-save would. Use strided slicing.
- `BaseModelArgs.from_dict` silently drops unknown config keys — "present but unread" is invisible by
  construction. Audit configs key-by-key against the modeling file (Motif's PolyNorm lesson). Solar:
  clean except inert `partial_rotary_factor` (NoPE) and one latent default-direction mismatch
  (`kda_allow_neg_eigval`) — check your port the same way.

## Transferable lessons

1. **A global keep-best scalar will sacrifice your weakest-measured slice** — gate per slice (strictly),
   and gate on the metric you ship, not a surrogate.
2. **Loop-rate and KL decouple at low bits** — a build can top the KL table while looping on greedy;
   ship-block on new `LOOPED` regardless of KL rank ([DPO-for-quantized-LLMs](https://arxiv.org/abs/2407.03051)
   documents the same decoupling and repairs behavior, not KL).
3. **Teacher = your strongest loadable reference**; an intermediate student-teacher re-exports its own
   damaged slices.
4. **Self-generated calibration data is off-policy** — it propagates the student's degeneration into the
   distillation inputs; coverage-stopping fixes expert coverage, not behavior.
5. **Chokepoint tensors first in any predicate**: linear-attention state projections, router/bias,
   untied embed/head (doubly so with a non-English tokenizer and a language-consistency eval).
6. **Reproduced beats recomputed**: every number here was re-measured independently before it was
   believed; the two eval runs agreeing bit-for-bit is what made the autopsy possible.
